**Recommendation:** expose CPA Manager's retained analytics through a narrow authenticated Prox adapter, keeping CPA Manager the sole usage consumer and owner of accounting, pricing, retention, and metadata projection. ## Findings that change the implementation brief

1. **Requests, attempts, and usage rows are different units.** A core reporter gets an execution UUID, while its parent trace identifies an inbound request. Retries and image-tool usage can yield multiple rows. CPA drops the execution UUID from its typed event and deduplicates by a content hash rather than `(instance, execution)`. Label existing counts “retained usage events” or explain their attempt semantics. Do not present them as exact unique inbound requests. `C:internal/runtime/executor/helps/usage_helpers.go:126`, `C:internal/runtime/executor/helps/usage_helpers.go:526`, `M:apps/manager-server/internal/usage/event.go:867`, `M:apps/manager-server/internal/usage/event.go:1329`.
2. **Configured sources are not stored usage provenance.** Prox has explicit instance IDs and authenticated source lifetimes. CPA's extra collectors share a store but do not add an instance ID to events. A provider or credential source is not a substitute for an instance. Historical attribution must remain unknown unless independently provable. `P:src/domain/providerSources/types.ts:1`, `P:src/services/api/sourceSession.ts:8`, `M:apps/manager-server/internal/worker/extra_collectors.go:14`, `M:apps/manager-server/internal/collector/collector.go:405`.
3. **“Redis queue” is an in-process delivery mechanism.** HTTP/RESP polling removes records before the consumer stores them. Subscription bypasses the queue and disconnects slow subscribers at a bounded buffer. There is no durable offset/acknowledgement or automatic replay of the missing interval. `C:internal/redisqueue/queue.go:9`, `C:internal/redisqueue/queue.go:65`, `C:internal/redisqueue/queue.go:141`, `C:internal/api/handlers/management/usage.go:23`.
4. **TTFT is not one measurement.** Some executors measure substantive streaming content; many measure the first body byte; fallback uses first packet; unset becomes numeric zero. Latency starts at reporter creation, not necessarily inbound receipt, and ends when the report is published. Subtracting the two does not produce a defensible generation interval. `C:internal/runtime/executor/helps/usage_helpers.go:126`, `C:internal/runtime/executor/helps/usage_helpers.go:433`, `C:internal/runtime/executor/helps/usage_helpers.go:720`.
5. **Canonical token accounting exists in core but loses fidelity in CPA.** Core emits schema-v2 buckets and accounting quality. CPA validates complete canonical evidence for cache normalization, but does not persist/expose the full canonical output partition, quality, or presence state as typed fields. Reasoning is a subset of OpenAI/Claude output, but separate from Gemini candidate output. A generic input + output + reasoning stack is wrong. `C:sdk/cliproxy/usage/accounting.go:8`, `C:internal/runtime/executor/helps/usage_helpers.go:1078`, `C:internal/runtime/executor/helps/usage_helpers.go:1201`, `C:internal/runtime/executor/helps/usage_helpers.go:1258`, `M:apps/manager-server/internal/usage/event.go:343`.
6. **CPA has substantial pricing and retention machinery already.** It has context/service tiers, configured-zero flags, pricing rollups, recovery checks, archives, and response coverage warnings. Reuse these owners. The price map still keys by model string; missing price can return zero; rate-only changes revalue historical tokens. “Estimated API-equivalent cost at current configured rates” is a supportable description, subject to the accounting issues below. `M:apps/manager-server/internal/model/model_price.go:3`, `M:apps/manager-server/internal/service/pricing/cost.go:38`, `M:apps/manager-server/internal/model/model_price_rules.go:251`, `M:apps/manager-server/internal/service/monitoring/service.go:1593`.

## 1. End-to-end ownership and delivery

### Core capture and dispatch

Executors construct `UsageReporter`, parse upstream usage, publish a success/failure detail, and dispatch `usage.Record` through registered plugins. The queue plugin serializes a richer wire envelope. There is no universal durable access ledger at this boundary.

- `Record` includes provider, upstream base URL, executor type, model/alias, auth IDs, source, client-key identity, requested/effective/response service tiers, response model, session hierarchy, generation/stream flags, timing, failure detail, tokens, and response headers. `C:sdk/cliproxy/usage/manager.go:24`.
- Reporter creation assigns a fresh UUID and records `time.Now()`. `sync.Once` means the first publication wins for that reporter; later usage/outcome corrections cannot replace it. `EnsurePublished` emits an empty successful detail if nothing has been emitted. It is used on many, but not all, execution paths. `C:internal/runtime/executor/helps/usage_helpers.go:126`, `C:internal/runtime/executor/helps/usage_helpers.go:560`, `C:internal/runtime/executor/helps/usage_helpers.go:585`.
- The dispatcher uses an in-memory slice and sequential plugin invocation. Shutdown drains queued work, but publication after closure returns without storing; no plugins means discard; plugin panic is recovered/logged without retry. Do not infer durable delivery from an accepted generation request. `C:sdk/cliproxy/usage/manager.go:451`, `C:sdk/cliproxy/usage/manager.go:501`.
- The queue plugin requires both queue enabled and usage statistics enabled. It writes `request_id` from logging context, `execution_id` from the record UUID, and `trace_id` from the record/context. It does **not** serialize every `Record` field: notably `BaseURL` and `AuthID` are not corresponding envelope fields. It does include raw client API key, credential source, response headers, and failure text, so it is not a browser-safe feed. `C:internal/redisqueue/plugin.go:22`, `C:internal/redisqueue/plugin.go:68`, `C:internal/redisqueue/plugin.go:129`, `C:internal/redisqueue/plugin.go:181`.

### Queue loss and consumer behavior

| Boundary | Actual behavior | Analytics consequence |
|---|---|---|
| Queue disabled | Enqueue returns; disabling clears queued items and closes subscribers | Unrecoverable gap unless another independently retained source exists |
| Polling retention | Default 60 seconds; configured maximum 3,600 seconds; prune occurs during enqueue/pop | A collector outage can exceed retention; this is not historical storage |
| HTTP/RESP pop | Same `PopOldest` removes items before response delivery | A response failure, consumer crash, normalization/store failure after pop loses data |
| Subscription | 256-item channel; live events bypass queue while subscribers exist | Subscription is not a replayable stream |
| Full subscriber buffer | Subscriber removed/closed; publish still returns true for that call | The triggering event can be lost when all subscribers reject it; no queue fallback for that event |
| Reconnect | Subscribe registers a new channel, sends a control message; it does not drain prior queue items | Events accumulated during a disconnect are not automatically replayed to the subscription |
| Multiple consumers | Pollers compete; live subscriptions get broadcasts | Prox must not become a second usage consumer; stream fanout still changes delivery behavior |

Evidence: `C:internal/redisqueue/queue.go:9`, `C:internal/redisqueue/queue.go:43`, `C:internal/redisqueue/queue.go:65`, `C:internal/redisqueue/queue.go:141`, `C:internal/redisqueue/queue.go:162`, `C:internal/redisqueue/queue.go:199`, `C:internal/api/redis_queue_protocol.go:234`.

CPA collector `auto` tries subscription first, then HTTP if subscription never established, then RESP if HTTP is unsupported. Once subscribed it reconnects with backoff. HTTP polling defaults to 500 ms in config; runtime values were not inspected. `processItems` ignores control frames, normalizes each payload, attempts dead-letter storage for invalid JSON, enriches snapshots, inserts, and only then invokes downstream handlers for newly inserted hashes. Dead-letter write errors are ignored while the status counter increments. An insertion failure returns to the reconnect loop without a durable pending batch. Status counters are process state, not evidence of total upstream traffic or exact loss. `M:apps/manager-server/internal/collector/collector.go:140`, `M:apps/manager-server/internal/collector/collector.go:229`, `M:apps/manager-server/internal/collector/collector.go:350`, `M:apps/manager-server/internal/collector/collector.go:405`, `M:apps/manager-server/internal/config/config.go:174`.

**Version distinction:** core offers `/v8/management/observability/usage/queue`; its legacy queue route also remains registered. CPA's HTTP collector currently builds `/v0/management/usage-queue`. Neither endpoint is suitable for Prox analytics reads. CPA's separate `/v0/management/monitoring/analytics` is a retained-data API and is not the same API family as the deprecated core management endpoints. Keep Prox core calls on v8 and give any CPA adapter an explicit service contract. `C:internal/api/server_management_v8.go:40`, `C:internal/api/server_management.go:93`, `M:apps/manager-server/internal/httpqueue/client.go:114`, `P:src/utils/constants.ts:17`.

### Multiple configured instances

Extra CPA collectors use the same store, primary management key/settings, and rollup handlers; automation stays on the primary connection. `RuntimeConfig` carries upstream URL into collector callbacks, but normalized `Event` does not carry it. Therefore the fact that a collector knew an upstream does not prove that retained rows can be grouped by it. Auth snapshot resolvers enrich against their collector’s connection; the persisted auth index still lacks an instance namespace. `M:apps/manager-server/internal/worker/extra_collectors.go:14`, `M:apps/manager-server/internal/collector/collector.go:36`, `M:apps/manager-server/internal/collector/collector.go:510`.

Core `Source` resolves to account/project/email/API-key information. CPA masks it and stores a hash of the trimmed original. It is credential attribution, potentially shared across instances. Provider, source hash, auth index, label, and proxy instance must remain distinct dimensions. `C:internal/runtime/executor/helps/usage_helpers.go:848`, `M:apps/manager-server/internal/usage/event.go:814`, `M:apps/manager-server/internal/usage/event.go:1315`, `M:apps/manager-server/internal/usage/RULES.md:1`.

### Retries, cancellations, and trace gaps

The conductor has retry rounds and credential/model selection loops for nonstream, count, and stream execution. Reporters are constructed within executor calls, so repeated executor calls normally create distinct execution IDs. Internal reconnect/replay within an executor can reuse a reporter. Neither queue envelope nor CPA typed event provides an attempt number, retry reason, retry-parent edge, or explicit “final inbound outcome” record. Preselection failures need not reach any reporter. `C:sdk/cliproxy/auth/conductor_execution.go:134`, `C:sdk/cliproxy/auth/conductor_execution.go:248`, `C:sdk/cliproxy/auth/conductor_execution.go:483`, `C:sdk/cliproxy/auth/conductor_execution.go:915`.

Cancellation semantics are not uniform: plugin streams publish failure with buffered usage; Claude uses a cancellation-policy helper and buffer; Gemini distinguishes terminal delivery; Antigravity waits on explicit HTTP delivery. A cancellation before any usage may produce zero tokens, partial tokens, or no record depending on branch. There is no persisted enum distinguishing client cancel, upstream cancel, timeout, truncation, admission failure, and terminal success. Do not infer cancel from a zero-token row or a generic 500. `C:internal/pluginhost/adapters_executors.go:896`, `C:internal/runtime/executor/claude_executor_stream.go:350`, `C:internal/runtime/executor/gemini_executor.go:380`, `C:internal/runtime/executor/antigravity_executor_stream.go:227`, `C:sdk/cliproxy/usage/stream_delivery.go:18`.

Queue failure serialization reports success as status 200 and falls back to 500 for failures lacking a status. It can also inspect the logging context’s response status. These are reporting conventions, not preservation of every actual HTTP status from every attempt. `C:internal/redisqueue/plugin.go:244`.

There are concrete silent-omission paths, beyond zero-token fallback. `StreamUsageBuffer.Publish` does nothing unless usage was observed. Claude streaming defers that method without a general `EnsurePublished`; Kimi's chat stream also defers it and can return directly on cancellation while sending a chunk. A no-usage successful completion can therefore be absent, and a buffered publication after some cancellations can retain success unless an error path published first. This is a source-level coverage concern, not a measured failure rate. Add transport-specific no-usage/cancellation fixtures before claiming all requests are counted. `C:internal/runtime/executor/helps/usage_helpers.go:982`, `C:internal/runtime/executor/claude_executor_stream.go:350`, `C:internal/runtime/executor/kimi_executor.go:373`.

## 4. Normalization, deduplication, storage, retention, and reads

### Normalization and identity

CPA chooses display model from alias/requested model, then resolved model; `AnalyticsModelForRequest` strips only recognized reasoning suffixes. It preserves requested/resolved/response names separately. Do not collapse an arbitrary custom alias with parentheses. `M:apps/manager-server/internal/usage/event.go:818`, `M:apps/manager-server/internal/usageidentity/model.go:39`.

`buildEventHash` hashes parent request ID, timestamp string, endpoint, display model, auth index, source hash, input/output/reasoning, maximum legacy cached/cache count, failed flag, and optional latency. It omits provider, instance, execution UUID, TTFT, cache-creation/read-specific fields, service tier, response model, and client metadata. Consequently:

- It is not a stable execution identity or a full content hash.
- Distinct events differing only in omitted fields can deduplicate. This is a structural possibility, not a measured production collision rate.
- Retries will often remain separate because timestamps/latencies/outcomes differ; “all retries are deduplicated” would also be false.
- The same event arriving with changed hashed normalization fields may fail to deduplicate.

Storage enforces unique `event_hash`, with an identity ledger retained across raw archival/deletion. Batch insertion validates canonical hashes, checks ledger/raw duplicates, and transacts ledger plus raw inserts. Future instance/execution IDs need a migration/versioned identity policy that preserves existing ledger identities and archive restoration behavior. `M:apps/manager-server/internal/usage/event.go:1329`, `M:apps/manager-server/internal/repository/usageevent/repository.go:287`, `M:apps/manager-server/internal/repository/usageevent/repository.go:380`, `M:apps/manager-server/internal/repository/sqlite/migrate.go:232`, `M:apps/manager-server/internal/repository/sqlite/migrate.go:588`.

### Rollups and coverage

CPA has raw events, permanent hourly aggregates, account/dashboard rollups, pricing-band rollups, monitoring projections, and checkpoints. Collector fanout receives only newly inserted events. Hourly worker defaults are 1,000 events/batch, 10 batches/pass, 30-second checks with wake/catch-up support. Public services choose eligible aggregate readers, recover using retained event projections where supported, and otherwise use raw queries or expose failure/limited coverage. Consumers should call these contracts, not read tables or reproduce rollup arithmetic. `M:apps/manager-server/internal/repository/sqlite/migrate.go:169`, `M:apps/manager-server/internal/repository/sqlite/migrate.go:328`, `M:apps/manager-server/internal/repository/sqlite/migrate.go:490`, `M:apps/manager-server/internal/worker/usage_event_fanout.go:24`, `M:apps/manager-server/internal/worker/usage_hourly_aggregate.go:15`, `M:apps/manager-server/internal/service/monitoring/service.go:1021`.

Pricing coverage compares conserved metrics per bucket/model/billing-model/tier/outcome, including token sums and latency samples. This is stronger than just matching global counts. It does not prove upstream capture completeness or correct external price data. `M:apps/manager-server/internal/store/usage_pricing_coverage.go:18`.

Automatic archive retention is disabled by default; the configured default duration when enabled is 30 days. This is source default evidence only. The worker creates/resumes archives, verifies them, then deletes eligible raw data through the archive service. Permanent aggregates/projections can survive, but event details and percentiles may require raw events. Never substitute a blanket “30-day retention” statement without reading an authorized status/config contract later. `M:apps/manager-server/internal/config/config.go:27`, `M:apps/manager-server/internal/worker/usage_archive_retention.go:122`, `M:apps/manager-server/internal/worker/usage_archive_retention.go:184`.

Analytics response coverage distinguishes mixed/aggregate-only ranges, raw-deletion counts, comparison/auxiliary ranges, and fidelity limitations. It is chiefly a raw-archive availability statement. ### Query and export contracts

`POST /v0/management/monitoring/analytics` authorizes panel access before reading. ## 5. Pricing and the registered-model table

### What can be reused

It supports models.dev, LiteLLM, and OpenRouter sync sources. Current numerical defaults are code rules, not evidence of actual contracted provider prices. Cache-read fallback can use legacy cache rate or 10% of prompt; cache-creation fallback can use prompt price; some models have special behavior. Do not copy a simplistic `input * inputRate + output * outputRate` formula into Prox. `M:apps/manager-server/internal/service/pricing/cost.go:38`, `M:apps/manager-server/internal/service/pricing/cost.go:117`, `M:apps/manager-server/internal/service/pricing/cost.go:149`, `M:apps/manager-server/internal/service/pricing/cost.go:185`.

### Pricing correctness gaps to resolve before stronger claims

- **Unpriced is currently capable of becoming `$0`.** Several pricing entry points return zero when no model price matches. Summary cost is a number, not a money-plus-coverage value. Preserve explicitly configured free prices, but expose unmatched/partially priced rows and tokens separately. Price-match and token-measurement coverage are independent.
- **Historical rates are not frozen.** Analytics holds a current model-price read lock while reading usage bands and applying prices. Price structure revision deliberately excludes rate-only changes. This provides within-query consistency, not ingestion-time price versions. Existing historical totals can change after a rate edit. `M:apps/manager-server/internal/store/store.go:288`, `M:apps/manager-server/internal/model/model_price_rules.go:251`, `M:apps/manager-server/internal/service/monitoring/service.go:4607`.
- **Output billing is not protocol-neutral.** Core Gemini stores candidates in `OutputTokens` and thoughts separately, whereas OpenAI/Claude output includes reasoning. CPA aggregates `output_tokens`; `pricing.ModelTokens` has no reasoning field; cost functions price only that output count. For Gemini-family data with positive separately reported thoughts, equivalent output billing can omit those thoughts if the intended price charges them as output. Fix in the accounting/pricing owner, with provider-aware canonical output, rather than adding reasoning globally. `C:internal/runtime/executor/helps/usage_helpers.go:1258`, `M:apps/manager-server/internal/repository/usageevent/analytics.go:543`, `M:apps/manager-server/internal/service/pricing/cost.go:13`, `M:apps/manager-server/internal/service/pricing/cost.go:138`.
- **Outbound tier is dropped.** Core sends client-requested, effective outbound, and response tiers. CPA chooses its billing tier from request/legacy/response with a Codex-specific preference for request tier, ignoring core `effective_service_tier`. Payload rules can change the effective tier. Persist all three and resolve billing explicitly. `C:internal/redisqueue/plugin.go:169`, `M:apps/manager-server/internal/usage/event.go:224`, `M:apps/manager-server/internal/usage/event.go:836`.
- **Response-model substitution is retained but not automatically the billing key.** Pricing callers use billing/resolved model and display alias candidates; the requested alias alone must not decide provider cost. A model returned in response metadata is evidence, but requires an owner rule before changing billing identity. `M:apps/manager-server/internal/service/pricing/cost.go:185`, `M:apps/manager-server/internal/service/monitoring/service.go:4616`.
- **The key is model-only.** SQLite uses `model text primary key`; the price map has no provider, proxy instance, endpoint, region, account contract, currency, or effective-time key. Two sources serving the same alias cannot have independently keyed rates through the current contract. `Source` in a price means price-data provenance, not proxy identity. `M:apps/manager-server/internal/repository/sqlite/migrate.go:725`, `M:apps/manager-server/internal/model/model_price.go:3`.
- **Alias matching is nuanced, not universally unsafe.** Sync tries exact, case-insensitive, source-model alias, provider-prefix tail, and normalized matches. It selects unique matches within a source, has models.dev official-model preference, and returns suggestions/unmatched results for ambiguity. These safeguards do not solve provider-specific runtime price-book collisions or semantic alias changes over time. `M:apps/manager-server/internal/service/modelprice/service.go:1243`, `M:apps/manager-server/internal/service/modelprice/service.go:1319`, `M:apps/manager-server/internal/service/modelprice/service.go:1349`.
- **Non-token charges are outside the model.** Speech/media/tool requests may be billed per duration, image, tool call, or other units. The audited price structure is token-rate based; a zero-token media event cannot be priced as free.

Price structure edits after raw deletion have guarded rebuild/coverage checks and can fail when no compatible retained source exists. Rate-only changes have different implications from model/threshold changes; an eventual price editor must surface owner errors rather than silently dropping historical coverage. `M:apps/manager-server/internal/repository/modelprice/repository.go:221`, `M:apps/manager-server/internal/repository/usagepricing/projection_read.go:72`, `M:apps/manager-server/internal/store/usage_pricing_coverage.go:18`.

### Registered models by provider

Core runtime `ModelInfo` has model ID, ownership/type, display metadata, token limits, modalities, and capabilities, but no prices. Runtime availability, configured registration, price-book membership, and historical usage are four different sets. A model with no requests still belongs in a registered-model table; a historical model can disappear from the current registry. `C:internal/registry/model_registry.go:39`.

CPA's existing runtime pricing-status endpoint discovers only the configured primary upstream and returns a list of model names plus exact-map unpriced names. ### Minimum owner-level contract additions

These are research recommendations, not implemented changes:

1. **CPA ingestion identity:** collector configuration supplies stable `instance_id`; promote core `execution_id` and parent trace into typed event/store/projection. Use an explicit versioned dedupe migration; do not recompute existing hashes wholesale. Include ingestion time, producer schema/version, collector identity, and measured coverage intervals. Public source descriptors remain secret-free.
2. **Core measurement:** separate upstream-send, first-byte, first-substantive-token, terminal-read, downstream-completion and inbound lifecycle timing. Attach method/presence flags and outcome kind. Record model side calls and retry edges. Preserve observed token usage on cancellations; mark partial/unknown rather than estimating a successful completion.
3. **CPA accounting:** persist canonical v2 token partition and quality/presence; normalize billable output once. Preserve provider raw values for diagnostics through the owner contract. Cache accounting inference must be identifiable as inferred; absent/zero usage and missing/zero rates must remain distinguishable.
4. **CPA pricing:** expose owner-computed per-event and aggregate cost with matched model/provider, rate source, timestamp/revision, current-rate vs frozen-rate semantics, known subtotal and unpriced counts/tokens. Add provider qualification only with a defined key migration. An ingestion-time dollar snapshot is required if historical rate reproducibility becomes a requirement.
5. **CPA query/metadata:** extend the authenticated analytics contract with source filters, explicit include/field policy, stable event identity, omitted safe metadata, and measurement/ingestion coverage. Raw JSON and failure-body access must remain internal; generic “return all fields” is unacceptable.
6. **Prox adapter/UI:** own only connection/auth scope, validation and safe DTO transport; call CPA accounting/pricing/query contracts. Use existing registry/session/lease lifetimes. A new analytics domain may own report filters and presentation contracts, but must not recreate billing rules or take over CPA consumption.

For each extraction/consolidation needed later, first lock current behavior with regression fixtures; make accounting changes independently reviewable. Existing duplicated CPA browser pricing must not become a third implementation in Prox. The immediate research crux is whether the initial release accepts retained aggregate scope with explicit gaps, or requires reliable per-instance requests and measurement first.
