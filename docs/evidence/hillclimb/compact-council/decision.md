# Council: compact Prox review blockage

**Headline:** Conflicting scores combined two reading concerns, while the checks missed text runs and enforced no compact-height limit.

**Brief:** Resolve the remaining reading difficulty in compact account rows without hiding names, losing quota meaning or increasing their footprint.

**Phase 0 reframe:** Diagnose the actual association difficulty before changing the UI.

## Options and assignments
Five options were considered: retain and diagnose; adjust warning grouping; add per-row window labels; broader hierarchy redesign; or a bounded grouping experiment with paired decimal reviews.
A Lean++ council used native Astra/high roles equivalent to the skill seats: Metis for assumptions, Explorer for strategy and internal evidence, Momus for executability, and a separate Explorer for synthesis verification. This follows the Codex tier mapping and inherited model, rather than pretending the exact named OMO agents were available.
The strategist chose the smallest experiment; the researcher audited screenshots and measurement coverage; the adversary challenged diagnosis and acceptance. They worked independently. See phase0.md and phase2-*.md.

## Cross-attack
The strategist updated the proposal in response to the adversary and internal evidence (phase3.md):
- Distinguish incorrect readings from correctly answered associations that require rereading.
- Require at least two independent reviewers to locate the same grouping difficulty before testing a grouping change.
- Sample individual painted text runs, including nested names, warning labels and percentages.
- Exercise both provider sections and compare every row and section against the restored baseline.
- Treat decimal score changes as judgments supported by observations, not precise usability measurements.

## Synthesis
**Decision:** Continue with diagnosis and, if repeated grouping difficulty is found, one mobile warning-inset experiment. Keep the deployed compact version unless evidence supports the candidate. Per-row labels remain a separate option only if window identification is the demonstrated problem.

**Acceptance:** Use the same three independent reviewers and eight-aspect rubric for paired fresh scores in 0.1 increments. Keep historical integer records untouched. All 56 existing candidate medians must reach 9.0; do not round 8.9 to a pass. At least two reviewers must describe reduced difficulty in the diagnosed association, with no new incorrect associations. Use neutral image identifiers and counterbalanced order; an improvement limited to candidate-second comparisons is inconclusive.

Preserve full visible names, balances, warnings, missing/stale meaning, colours, disclosure behavior and expanded details. Keep the existing contrast/hue/target thresholds. Compare both providers in all eight capture states: each section and closed row may grow by at most 0.5 CSS px measurement tolerance, with no additional name/warning lines. Expanded layouts must remain unchanged. Newly failing checks or meaningful regressions reject the candidate. Continue to use the skill's two-round stopping rule and report full decimal matrices.

**Why:** The restored pixels already preserve all information. The remaining plausible issue is reading effort between wrapped names and subordinate warnings. Historical feedback does not justify a broader redesign or hiding names.

**Survival Score: Modified.** The original hybrid gained explicit diagnosis, contrast coverage, both-provider interactions and compact-height requirements after challenge.

**Trade-offs:** One small experiment may fail; retaining the current UI is preferable to shipping a regression. Decimal scores reveal smaller judgments but are not population-level usability measurements.
**Second-order consequences:** Better capture coverage makes future regressions detectable without creating a new test framework.
**Open risks:** Familiarity with the repeated reading task may bias comparisons. Fresh baseline scoring can differ from historical scores without any UI change.
**Dissent:** The adversary's acceptance objections were incorporated. No claim of resolved hierarchy or completed hillclimb is made.
**Phase 5:** Skipped; no OpenSpec change.
**Phase 6:** In progress. Direct-main commits and deployment follow the user's standing instructions; no PR overhead.
**Cost:** Actual council token usage is unavailable; six council agent invocations including verification, with separate UI review agents.

## Follow-through after paired reviews

The first decimal pair scored the unchanged baseline at 43/56 and the mobile inset at 45/56, with all three reviewers describing less association effort and no score drops. A second paired round added a nesting rule and reached 46/56. Historical integer scores are unchanged; this is a fresh decimal baseline, not a claimed regression on identical pixels.

The remaining mobile layout feedback conflicts (more versus less space before the warning). No spacing change is inferred from that disagreement. All three reviewers independently identify excessive desktop label/value distance. The next bounded experiment extends warning grouping to closed rows at other widths and caps their inline size at 28rem. Expanded rows retain their original layout. This continues the authorized compact-account hillclimb on new evidence; it is not a wider dashboard redesign.

For that deliberate width change, numeric preservation checks compare each warning's right edge with its own primary balance, rather than requiring the old screen coordinate. The 0.5px height tolerance, unchanged line counts, full names/values/status, contrast, targets, provider colours, and 9.0 subjective threshold remain. The original mobile candidate's unchanged absolute value positions were already verified.

## Release boundary

The independent decimal reviews improved the fresh baseline from 43/56 to 55/56. Two subsequent review rounds found no meaningful gain from the spacing/connector variants, so those variants were removed. The initial 56/56 acceptance condition remains unmet; it is not silently waived or reported as passed. The user's standing instruction to retain the compact layout and finish deployment authorizes releasing the best verified improvements with that limitation reported.
